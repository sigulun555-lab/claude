# totoGOAL（Claude側）× toto Insight（ChatGPT側）連携ガイド

## 1. Jリーグ toto予想への対応状況（確認結果）

totoGOAL 究極予想エンジンは、もともとJリーグ toto（13試合・1=ホーム勝ち／0=引き分け／2=アウェイ勝ち）の構造にそのまま対応しています。今回、既存機能（予想スコア計算・V1/V2ロジック比較表示・ライブ速報反映など）には手を加えず、新しい出力関数を追加する形で連携用JSONの出力機能を実装しました（アーティファクトVersion 96として公開済み）。

## 2. 追加した機能

アーティファクト内の「🔗 連携用JSON出力（ChatGPT側との比較用）」パネルから、現在表示中の開催回について以下を含むJSONを生成できます。

- 開催回・試合番号・ホーム/アウェイチーム名
- 1（ホーム勝ち）／0（引き分け）／2（アウェイ勝ち）の確率（必ず合計100%になるよう正規化）
- 予想作成日時（predictedAt）
- 参照データの出典（dataSource.name）と取得日時（dataSource.retrievedAt）
- 負傷・欠場・出場停止情報（injuryInfo。統計的リスク値として保持している選手のみ記載）
- 予想モデルの名称（modelName）

**取得できていない項目は、推測で埋めずに「未取得」と明記**しています。具体的には、Claude側はチーム・試合ごとの「データ取得日時」を構造化データとして保持していないため `retrievedAt` は常に「未取得（…）」、出場停止情報も管理していないため `suspensions` は常に「未取得（…）」と出力されます。欠場リスクは0〜1の統計的スコアのみ保持しており、個別の負傷名や罹患日などの詳細は「未取得」です。

## 3. サンプルJSON

第1664回・13試合分を実際に生成した出力を添付しました（`toto_claude_sample_round1664.json`）。確率合計が100%から浮動小数点誤差（最大 2.2×10⁻¹⁶）の範囲内に収まっていることも検証済みです。

## 4. ChatGPT側（gpt リポジトリ）との比較

ChatGPT側（`sigulun555-lab/gpt`）を調査した結果、次のような仕組みでした。

- GitHub Actionsが6時間おきに起動し、`k-addtimes/jleague_open_data`（コミュニティミラー。toto公式データではないと明記）からJリーグの日程・結果CSVを取得
- toto公式ページをパースして開催回・締切・対象13試合を確認
- 独立ポアソン分布のベースラインモデル（市場オッズブレンドなし、Dixon-Coles補正なし、負傷情報なし）で1/0/2の確率を計算
- `data/predictions.json` などをGitHub Pagesに公開し、ChatGPT Actionsがそれを読み取り専用APIとして参照

両者の `predictions`配列の確率キー（`"1"`/`"0"`/`"2"`）は同じ記法なので、直接見比べられます。主な違いは次の通りです。

| 項目 | Claude側（totoGOAL） | ChatGPT側（gpt） |
|---|---|---|
| モデル | 独立ポアソン＋市場オッズブレンド＋Dixon-Coles低スコア補正 | 独立ポアソンのみ（補正なし） |
| 負傷・欠場情報 | 統計的リスク値のみ保持、個別詳細は「未取得」と明記 | 常に「未取得」（機能自体がない） |
| データ取得日時の粒度 | 試合・チーム単位では「未取得」 | ラウンド単位で `lastSuccessfulFetch` あり |
| 更新方式 | アーティファクトを開いた都度、手動でJSON生成 | GitHub Actionsで自動・定期更新 |

## 5. 連携手順

### 現時点ですぐできること（手動比較）
1. totoGOALアーティファクトで対象の開催回を選び、「📤 JSONを生成して表示」→「📋 コピー」または「💾 ダウンロード」で `toto_predictions_round<開催回>.json` を取得する。
2. ChatGPT側の `https://sigulun555-lab.github.io/gpt/data/predictions.json` を開き、同じ開催回のものを見比べる。
3. 試合ごとに1/0/2の確率とpick（最大確率側）が食い違う試合を洗い出し、どちらの予想が実際の結果に近かったかを継続的に記録する。

### 今回わかった制約（ご確認・ご判断をお願いしたい点）
今回のセッションでは、GitHubの `sigulun555-lab/claude` リポジトリ（Claude側の連携用リポジトリ）に直接アクセスできませんでした。

- このセッションのGitHubトークンが無効で、`gh` コマンドでの認証が失敗
- `gh api repos/sigulun555-lab/claude` はHTTP 403（「このリポジトリへのアクセスはこのセッションで有効になっていません」）
- 匿名の `git clone` も、`claude` リポジトリが非公開のため失敗（公開リポジトリの `gpt` の方は匿名cloneで読めました）

そのため、サンプルJSONと本ガイドは今回はこの場でお渡しする形としました。`claude` リポジトリに実際にコミットして連携を自動化したい場合は、以下のいずれかの方法をご検討いただけますでしょうか。

- このセッションに `claude` リポジトリへのアクセスを許可する設定を行っていただく（可能であれば）
- 一時的にリポジトリを公開にしていただく（`gpt` と同様の匿名clone手順が使えるようになります）
- 添付した2ファイル（サンプルJSONとこのガイド）を、お手元の環境からご自身で `claude` リポジトリにコミットしていただく

### 将来的な自動化の方向性（ChatGPT側と対称な構成にする場合）
ChatGPT側と同じパターンに揃えるなら、以下のような構成が考えられます。

1. `claude` リポジトリに `data/claude_predictions.json` のような固定パスを用意する。
2. 開催回が確定するたびに、このアーティファクトでJSONを生成し、そのファイルにコミットする（現状は手動。将来的にはアーティファクト側からの自動コミットも検討可能）。
3. GitHub Pagesを有効化し、ChatGPT側の `GPT-ACTION-openapi.json` と同じ形式で、Claude側用のOpenAPI定義（`getLatestClaudeTotoForecast` など）を用意する。
4. 両方のpredictions.json相当ファイルを定期的に突き合わせ、pickが分かれた試合を自動検出するスクリプト（`gpt` 側の `scripts/auto_pipeline.js` に近い発想）を書けば、比較作業自体も自動化できます。

ご希望であれば、上記の自動化部分（比較スクリプトやOpenAPI定義）も次のステップとして実装します。
